## Delivery order

1. Correct the presentation and add state/navigation regressions. Preserve all
   stable requirements/IDs, command guards and server-private identities.
2. Pass unit, type, documentation and source checks. Run bounded browser/geometry
   fixtures only on M1, through one scenario entry; no developer-Mac browser.
3. Freeze the changed source and assemble one reviewed successor Setup/DMG using
   existing CARLA/Factory and verified caches. Never rebind a completed receipt.
4. Install through the normal retained-Test update owner, subject to real capacity
   and signing preflight. Preserve the current DMG, Test, data, dependencies and
   caches; do not delete retained M1 materials or weaken reserve checks.
5. One campaign owns the full API observation and visible UI scenario, including
   Platform publication-card checks, bounded geometry samples, independent effects
   and verified cleanup. No routine agent clicks or step scheduling.
6. Produce before/after screenshots and an explicit gate table. Merge/publication
   follows review, not merely a unit or fixture pass.

No polling timeout, service algorithm, Cloud authority, native layout authority,
at-most-once request protocol or Safe Stop policy is changed. Shared Docker is
not routinely restarted. The separate Setup candidate-image inventory limitation
is not qualified or hidden by retained-runtime Presenter checks.
