accepted Vehicle summaries and popup design, preserving earlier versions and

## Verification

Rebuild with `node scripts/build-mockup-2-10.cjs` after editing the source.
The build preserves the standalone wrapper and does not modify older mockups.

`node --test tests/mockups/mockup-2-10.test.cjs`, with the existing Presenter
Playwright package and installed Chrome supplied through `MOCKUP_PLAYWRIGHT`
and `MOCKUP_CHROME`, runs the isolated state and browser cases. Browser contexts
are fresh; all requests are intercepted with the standalone fixture or denied.
No operator profile, Cloud session, live Presenter port or VM is used.

Final result: **78 passed, 0 failed, 0 skipped** (74 state/source checks and
4 isolated browser suites). Documentation validation and `git diff --check`
also pass. The expanded gate covers:

- Full Create/start/publish/Provision story; VDP V1/V2/V3, Brake V1/V2/V3 and
  Tire V1; separate first Deploy and later replacement; backend results.
- Warehouse publication before Provision, monotonic release continuation,
  processing rejection, lost reply, reconciliation, interrupted operations.
- Safe Stop request while moving, gate loss during apply, reload and stale
  timers; service updates independent of Safe Stop.
- Offline local installation versus retained Cloud report, delayed receipts,
  unavailable Cloud observation and current-identity isolation.
- Park/Resume, normal and interrupted retirement, pending-update Finish,
  local shutdown while Cloud retirement is unconfirmed, next clean cycle.
- Both independent resets, matching CLEAR before completion, retained records,
  new warning, rejected changed binding, timeout and restart recovery.
- Inline summaries, dialog tabs, pagination, record detail/back, inventory
  detail/back, Escape, focus return and inert Studio background.
- Fully populated and pending layouts plus backend/Cloud dialog tabs at
  1728 × 1117, 1512 × 982 and 1280 × 720, with no page scrolling, panel overflow,
  overlapping architecture/guide/footer or dialog-body scrolling.
- Session lifecycle, Cloud selection, OEM/SP setup and simulation-only review
  tabs at all three sizes; access-prompt cancellation and same-profile release
  re-preparation. Browser geometry is measured after ResizeObserver completes,
  not just after advancing the simulated workflow clock.
- Byte-for-byte preservation of 2.8/2.9, original CARLA/brand images,
  source/standalone state-machine equivalence and absence of live clients.

### Deliberate simulation limits

Certificates, hashes, subjects, instances, resources and records are fixtures;
no credentials or files are read. Network/Cloud transport is accelerated:
Offline reports arrive after 6 s unless held; reconnect includes Connected then
Online after 1.8 s. These are **not** production timing promises. Review controls
can hold reports indefinitely. Physics/estimator input and packet serialization
are not reimplemented. Backend history does not assert a current native warning.
The internal historical deprovision/delete helpers remain test fixtures, not
advertised current Studio actions. Polling is an isolated simulation and is not
an implementation of the application's adaptive network scheduler.

## Remaining gates

User visual review is pending. Real data mapping, live polling/freshness,
application dialog integration, native desktop window placement and clean
first-Provision no-restart qualification are not established by these tests.
The simulated resource values and episodes are examples, not performance,
physics or product acceptance evidence. The current published source checkpoint
is unchanged; this new mockup is an uncommitted review increment until the user
requests publication.

The [delivery plan](../planning/active/demo-studio-delivery-plan.md) retains the
hold on actual UI integration. No package/image build, signing, upload, runtime
restart, Cloud mutation or disk cleanup was performed for this review.
